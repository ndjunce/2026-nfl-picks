# Phipps Tavern Speciality Picks 2026

A **static** website (instant load, no server, no cold-start) that shows a group's weekly NFL pick'em
picks, a live leaderboard, and a per-player "Path to Win" analysis. Friends can view the dashboard
on their phones and use a player access code to enter picks for spread weeks. The browser polls
ESPN's public scoreboard for live scores. The dashboard uses plain HTML/CSS/JS on GitHub Pages.

**Live:** https://ndjunce.github.io/2026-nfl-picks/

## Highlights
- **Live leaderboard** that grades picks automatically as games go final (ESPN public feed).
- **Path to Win** — for each player, the exact remaining games they need, tiebreaker-aware, plus an
  odds-weighted win-probability **estimate** computed by exact enumeration over the undecided games
  (a collapsible in-page note explains the full methodology). Honestly labeled an estimate.
- **Weekly archive** — past weeks stay browsable via week tabs (results + everyone's picks preserved).
- **Mobile-first** dashboard served from a CDN.

- **`index.html`** — the public dashboard and link to player entry.
- **`admin.html`** — backup organizer grid (click picks, generate `picks.js`).
- **`picks.js`** — the data file. Generated by admin.html; published by you via git push.

## Dashboard and admin grid
The dashboard and backup admin grid are static GitHub Pages files.
- **Friends** open `index.html`: they see picks + live scores. If they open `admin.html` and click,
  it only changes THEIR OWN browser — they **cannot publish** (no repo access).
- **Only you** change what everyone sees, by committing & pushing `picks.js` (needs your GitHub login).
- **Edit history (receipt):** every push is a timestamped git commit, AND each generated `picks.js`
  stamps an `_editLog` line — a double record of what was entered and when.

The admin grid does NOT auto-save to the cloud on purpose: an instant-save would require a secret
write-token in the public page, which a friend could read. The git-push flow is what guarantees only
you can publish.

## Player entry for spread weeks

Players open **Enter my picks** on the dashboard, choose their name and week, and enter their
individual access code. Each matchup shows both signed spreads. Players can save part of a card
and return to finish or change picks before each game's kickoff. The tiebreaker is the combined
score prediction for the last game and closes at that game's kickoff. Saved picks go directly into
that player's column on the weekly Sheet tab and show on the dashboard after a refresh.

### Organizer setup

1. Open the bound Apps Script from the picks Sheet. Update `Code.gs` and add an HTML file named
   `PickEntry` using the contents of `PickEntry.html`.
2. In **Deploy → Manage deployments**, edit the existing web app and deploy a **New version**.
   Keep the current `/exec` URL and access settings. The JSON feed continues to serve the dashboard.
3. Reload the Sheet and choose **Picks Tools → Issue a player access code…** for each player.
   Give each player their own code privately. Issuing a replacement invalidates the previous code.
   The dashboard link appears after the first code is issued.
4. Use the existing [spread week setup](SPREAD_MODE.md) for future ATS tabs. A game opens for entry
   when a verified ESPN spread is available or the organizer has already locked its line. The first
   accepted pick freezes the displayed line for everyone. If a line changes before a first pick saves,
   refresh the lines and confirm your choice at the new spread.

## ⏱ Weekly workflow (on your call — no file editing, no syntax)
1. Open **`admin.html`** (locally, or at `https://ndjunce.github.io/2026-nfl-picks/admin.html`).
   It auto-loads the current week's games from ESPN (or set Week/Season and click "Load").
2. **Click** each player's winner in the grid. **Type** each player's tiebreaker total (last game).
   Your entry auto-saves in your browser as you go (so you won't lose it mid-call).
3. Click **Generate picks.js** → **Download picks.js** (or Copy).
4. Replace `picks.js` in your local `2026-nfl-picks` folder, then:
   ```
   git add picks.js
   git commit -m "Week N picks"
   git push
   ```
5. Live site updates in ~1 minute. The commit is your timestamped receipt.

(Blanks are allowed — an un-clicked game just scores as a no-pick for that player.)

## 📄 Google Sheet picks — Apps Script web app (primary weekly input, no git push)
The whole season lives in **one Google Sheet, one tab per week** (`Week 1`, `Week 2`, …). A **Google Apps
Script** bound to that sheet is deployed as a **web app** that returns every week's picks as JSON at one
stable URL. The site fetches that single URL on load: the **newest week** drives the live view, **older
weeks** fill the archived week tabs. Winners/results are **not** in the sheet — they come from ESPN exactly
as today. `picks.js` (live) + `season.js` (archive) stay as the **automatic fallback**, so a sheet hiccup
never blanks the page. `admin.html` still works as a backup entry method.

Base sheet (already created, "Anyone with link → Viewer"):

Script: **`Code.gs`** in this repo.

### Step 1 — install the Apps Script (one time)
1. Open the sheet → **Extensions → Apps Script**.
2. Delete any starter code, **paste the full contents of `Code.gs`** from this repo, and **Save**.
3. Reload the sheet. A **"Picks Tools"** menu appears in the toolbar.

### Step 2 — deploy it as a web app (one time)
1. In the Apps Script editor: **Deploy → New deployment**.
2. Click the gear → **type = Web app**.
3. **Execute as: Me** · **Who has access: Anyone** → **Deploy**.
4. Approve the one-time Google authorization prompt (it's your own script reading your own sheet + calling
   ESPN's public scoreboard).
5. **Copy the Web app URL** — it ends in `/exec`, like
   `https://script.google.com/macros/s/AKfy…/exec`.
6. **Send me that `/exec` URL.** I paste it into `SHEET.jsonUrl` in `index.html` and test live. Until then the
   site keeps using `picks.js` + `season.js` exactly as before.
   > After any future edit to `Code.gs`, re-deploy: **Manage deployments → (edit) → Deploy** so the `/exec`
   > URL serves the new code.

### Step 3 — each week (from the "Picks Tools" menu)
1. **Picks Tools → Build week schedule…** → enter the week number. It pulls that week's NFL games from ESPN
   and writes a `Week N` tab (header + one row per game + a `TIEBREAKER` row) — you never hand-type games.
2. It automatically adds the per-game **dropdowns** (you can re-run **Picks Tools → Add dropdowns to a week…**
   any time). Each pick cell becomes a click-to-choose dropdown of just that game's two team abbreviations.
3. Everyone picks winners from the dropdowns; enter each player's **tiebreaker total** in the `TIEBREAKER`
   row (predicted total points for the **last** game — that's the tiebreaker game).
4. The site reflects it on the next load. No git push.

**Tab layout the script writes (and the site reads):**
```
team1,team2,Nick,Clyde,Chet,Henry,Riley,Bobby
```
one row per game (scoreboard abbreviations: `WSH`, `LAR`, `LAC`, `LV`, `SF`, `TB`, `NYG`, `NYJ`, …), then a
final row `TIEBREAKER` with each player's numeric total. Team **logos** show on the site automatically — a
text pick like `SEA` renders the Seahawks logo (the site already draws logos next to picks). **Honest limit:**
Google Sheets dropdowns are text-only, so the *in-sheet* dropdown shows abbreviations, not logos.

Ready-to-paste starter tabs are also in the repo — **`SHEET_TEMPLATE_Week1.csv`** and
**`SHEET_TEMPLATE_Week2.csv`** (the real Week 1/Week 2 picks) — if you want to seed those two weeks by hand
instead of via the menu (File → Import → Upload → "Replace current sheet" onto the matching `Week N` tab).

### Honest tradeoffs
- **Pro:** no weekly git push; one JSON URL for the whole season; games auto-pulled from ESPN; click-to-pick
  dropdowns; the same sheet drives both the live week and the archived week tabs.
- **Con:** the web app must stay deployed with **Access: Anyone** (picks only — nothing sensitive); the parse
  is only as reliable as the sheet's format — a renamed column or a typo'd abbreviation makes that week fall
  back to `picks.js`/`season.js`. Keep the header row + abbreviations as the script writes them.
- The git "receipt" trail is replaced by the **sheet's own version history** for sheet-entered weeks.

Future weeks are just the workflow above.

## Why static (not Render like last year)
Render free tier spins down → 30-60s cold-start. This is pure static files on a CDN → instant load,
no server to wake. The live scores run in each visitor's browser calling ESPN directly, so there's no
backend to host, sleep, or pay for.

## Notes / limits
- Live scores: ESPN public feed `site.api.espn.com/.../nfl/scoreboard` (free, no key). If it blips, the
  page keeps showing picks and fills scores in on the next 30s refresh (never blanks/crashes).
- Leaderboard counts a win only when a game is FINAL and ESPN marks a winner.
- Ties broken by closest tiebreaker (last game's total, once final).
- Everything is client-side; nothing to secure, no personal data.
